# Reviewed checks and execution boundaries

The primary plan was stated before execution: discover actual connections, separate source/test evidence from live reachability and physical devices, and import a tested manual verifier. This file records that procedure and the observed deviations.

1. **Baseline and source inventory:** read repository instructions; record `main`, source `e2aa41b`, published APK identity and installed n8n version. Parse source without importing runtime modules or reading `.env`/credentials into deliverables. Existing n8n SQLite is read-only during discovery.
2. **Behavioral evidence:** review V2 test setup for temporary DB/storage, test mode and local free-port HTTP servers. Run the complete unmodified suite. Record failures/skips and do not claim assertions after an early failure ran. The stale 2.0.6 filename caused one early rep-test failure; a temporary copy adapted only this expected metadata and ran the preserved scenarios separately. No application/repository-test fixes were made.
3. **Live checks:** GET-only local/public health, web and representative asset, n8n health and anonymous auth boundaries for each protected module. No protected business records, production writes or artificial authentication bypass. Request timeout 5 seconds, maximum two attempts, safe GETs only. Missing n8n credentials block authenticated acceptance.
4. **Generated structure:** installed n8n 2.46.7 node types/versions, unique names/IDs, expressions, code syntax, references/edges, inactivity, configuration declaration and embedded-secret patterns. Diagram-only notes must not claim executable business actions.
5. **Isolated n8n runtime:** new temporary `N8N_USER_FOLDER`, explicit temporary SQLite path, temporary encryption key and independent loopback fixture/runner ports. Import final JSON. Run synthetic success, then return HTTP503 for exactly one required health fixture. Require 17 other checks passing and an error execution / nonzero exit from the final gate. Run the same final workflow against actual live read-only URLs from the isolated n8n instance.
6. **Live delivery:** confirm chosen workflow IDs absent; snapshot live n8n SQLite to a protected external-storage directory; import two new inactive workflows into the existing personal project with the official CLI. Preserve existing workflows/credentials. Compare imported node and connection JSON to files. Execute only the new manual GET verifier and save execution metadata/final summary. Do not activate or schedule it.
7. **Final review:** parse every generated JSON/XML, compile/check Python/JavaScript audit tooling, confirm live links respond and project ownership exists, review Git diff and secret exposure. Commit/push only this audit directory to main under the existing deploy lock, so source/deployment code is not changed by the evidence publication.

The first two runtime attempts were rejected as acceptance evidence: unsupported sandbox `URL`, then the HTTP text response field adapter. Both were corrected in deliverables and all relevant runtime checks were repeated. The final successful and deliberately failed executions are the acceptance evidence; earlier error logs remain historical diagnostics.

Physical-device camera/GPS/SAF/biometric/background/upgrade/recovery acceptance is blocked because ADB lists no device. Native source and packaging tests are explicitly weaker evidence. No production restore, production financial/attendance/visit mutation, push/alert delivery or complete authenticated production business journey is performed by this n8n task.
